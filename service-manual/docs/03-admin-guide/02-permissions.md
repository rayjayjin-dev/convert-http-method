# 권한 관리

시스템의 접근 권한을 체계적으로 관리하는 방법을 안내합니다. 역할 기반 접근 제어(RBAC) 모델을 기반으로 권한을 설정하고, 조직의 요구에 맞는 커스텀 역할을 생성하는 방법을 다룹니다.

## 역할 기반 접근 제어 (RBAC)

본 시스템은 역할 기반 접근 제어(Role-Based Access Control) 모델을 사용하여 사용자 권한을 관리합니다.

### RBAC 구조

```
조직 (Organization)
  └── 역할 (Role)
        └── 권한 (Permission)
              └── 리소스 (Resource) + 동작 (Action)
```

### 핵심 개념

| 개념 | 설명 | 예시 |
|------|------|------|
| 역할 (Role) | 권한의 논리적 그룹 | 시스템 관리자, 편집자 |
| 권한 (Permission) | 특정 리소스에 대한 동작 허용 | 문서 읽기, 사용자 생성 |
| 리소스 (Resource) | 접근 대상이 되는 시스템 객체 | 프로젝트, 문서, 설정 |
| 동작 (Action) | 리소스에 수행할 수 있는 작업 | 생성, 읽기, 수정, 삭제 |

### 기본 제공 역할

시스템에서 기본으로 제공하는 역할은 다음과 같습니다:

| 역할 | 설명 | 수정 가능 | 삭제 가능 |
|------|------|-----------|-----------|
| 시스템 관리자 | 모든 리소스에 대한 전체 권한 | 아니오 | 아니오 |
| 프로젝트 관리자 | 프로젝트 범위 내 관리 권한 | 예 | 아니오 |
| 편집자 | 콘텐츠 생성 및 수정 권한 | 예 | 예 |
| 일반 사용자 | 기본 사용 권한 | 예 | 아니오 |
| 뷰어 | 읽기 전용 권한 | 예 | 예 |

:::note
기본 제공 역할 중 "시스템 관리자"와 "일반 사용자"는 시스템 운영에 필수적이므로 삭제할 수 없습니다.
:::

## 권한 설정

각 역할에 부여할 수 있는 세부 권한을 설정하는 방법입니다.

### 권한 매트릭스

리소스별로 부여 가능한 권한은 다음과 같습니다:

| 리소스 | 생성 | 읽기 | 수정 | 삭제 | 관리 |
|--------|------|------|------|------|------|
| 프로젝트 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 문서 | ✓ | ✓ | ✓ | ✓ | - |
| 작업 | ✓ | ✓ | ✓ | ✓ | - |
| 사용자 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 시스템 설정 | - | ✓ | ✓ | - | ✓ |
| 감사 로그 | - | ✓ | - | - | - |

### 권한 설정 방법

1. **관리자 패널** > **권한 관리** 메뉴로 이동합니다
2. 설정할 역할을 선택합니다
3. 리소스별 권한 체크박스를 설정합니다
4. **저장** 버튼을 클릭하여 변경사항을 적용합니다

:::warning
권한 변경은 해당 역할이 할당된 모든 사용자에게 즉시 영향을 미칩니다. 변경 전 영향 범위를 반드시 확인하세요.
:::

### 권한 상속

권한은 상위 레벨에서 하위 레벨로 상속됩니다:

- **조직 레벨**: 조직 전체에 적용되는 기본 권한
- **프로젝트 레벨**: 특정 프로젝트 내에서만 적용되는 권한
- **리소스 레벨**: 개별 리소스에 대한 세부 권한

```
조직 권한 (기본)
  ├── 프로젝트 A 권한 (오버라이드 가능)
  │     ├── 문서 1 권한 (세부 설정)
  │     └── 문서 2 권한 (세부 설정)
  └── 프로젝트 B 권한 (오버라이드 가능)
```

:::tip
하위 레벨에서 상위 레벨의 권한을 확장할 수는 없습니다. 상위에서 거부된 권한은 하위에서 허용할 수 없습니다.
:::

## 커스텀 역할 생성

조직의 특수한 요구사항에 맞는 커스텀 역할을 생성할 수 있습니다.

### 커스텀 역할 생성 절차

1. **권한 관리** > **역할 목록** 메뉴로 이동합니다
2. **+ 새 역할 생성** 버튼을 클릭합니다
3. 역할 기본 정보를 입력합니다:
   - **역할명**: 역할을 식별할 수 있는 이름
   - **설명**: 역할의 목적과 범위
   - **기반 역할**: 권한을 복사할 기존 역할 (선택)
4. 권한 매트릭스에서 필요한 권한을 선택합니다
5. **생성** 버튼을 클릭합니다

### 커스텀 역할 예시

| 역할명 | 기반 역할 | 추가 권한 | 제거 권한 | 사용 사례 |
|--------|-----------|-----------|-----------|-----------|
| QA 담당자 | 일반 사용자 | 작업 관리 | - | 품질 관리 전담 |
| 외부 협력사 | 뷰어 | 특정 프로젝트 편집 | 사용자 목록 조회 | 외부 파트너 접근 |
| 팀 리더 | 편집자 | 팀원 관리, 보고서 생성 | - | 팀 단위 관리 |
| 감사자 | 뷰어 | 감사 로그 조회, 보고서 | 콘텐츠 수정 | 내부 감사 수행 |

### 역할 관리 모범 사례

:::tip
커스텀 역할을 생성할 때는 다음 원칙을 따르세요:

- **최소 권한 원칙**: 업무 수행에 필요한 최소한의 권한만 부여합니다
- **역할 분리**: 상충되는 업무는 별도의 역할로 분리합니다
- **정기 검토**: 분기별로 역할과 권한의 적절성을 검토합니다
- **명명 규칙**: 역할명에 목적과 범위를 명확히 표현합니다
:::

## 권한 감사

권한 변경 이력을 추적하고 감사하는 방법입니다.

### 감사 로그 조회

| 로그 항목 | 설명 |
|-----------|------|
| 변경 일시 | 권한 변경이 발생한 시간 |
| 변경자 | 권한을 변경한 관리자 |
| 대상 | 변경이 적용된 역할 또는 사용자 |
| 변경 내용 | 이전 값과 변경된 값 |
| 사유 | 변경 사유 (입력된 경우) |

### 권한 리포트 생성

정기적인 권한 검토를 위해 다음 리포트를 생성할 수 있습니다:

1. **사용자별 권한 현황**: 각 사용자에게 부여된 모든 권한 목록
2. **역할별 사용자 현황**: 각 역할에 할당된 사용자 수 및 목록
3. **미사용 권한 분석**: 부여되었으나 사용되지 않는 권한 식별
4. **권한 변경 이력**: 지정 기간 내 모든 권한 변경 내역

:::note
감사 로그는 최소 1년간 보관되며, 규정 준수를 위해 삭제할 수 없습니다.
:::
